# Vibe Coding Workflow

一个通用、可交互、项目无关的 AI 软件开发工作流。

它帮助大模型在开始写代码前，先理解项目和需求，通过顺序访谈收集必要信息，再根据风险选择合适的开发流程，并在阶段门禁通过后执行任务。

> 工作流本身只需要复制 `.ai/` 目录，不会覆盖目标项目原有的 `README.md`、`AGENTS.md` 或其他根目录文件。

## 为什么需要它

直接让 AI “实现一个功能”通常会带来这些问题：

- 没有充分理解已有项目就开始修改代码
- 需求、范围和验收标准不明确
- 复杂任务和简单任务使用同样重量的流程
- AI 忽略已有架构、工程规范或历史决策
- 修改完成后缺少测试、回归和文档收尾

这个工作流把开发过程拆成可确认的阶段，并让 AI 在每个阶段明确自己的边界。

## 核心特性

- **顺序访谈**：每轮只询问一个关键问题，避免一次填写复杂问卷
- **可选方案**：AI 根据上下文给出推荐方案和可选项，用户选择后继续
- **Ready 门禁**：必要信息收集完成并得到确认后，AI 才开始执行任务
- **双项目模式**：区分空项目和已有项目，采用不同的前置流程
- **可选流程重量**：支持完整流程、轻量流程和 AI 自动推荐
- **阶段化开发**：需求、架构、计划、实现、验证和收尾各有明确边界
- **状态持久化**：通过 `.ai/STATE.md` 和 `.ai/TASKS.md` 保存协作上下文
- **语言适配**：交互语言跟随用户当前使用的语言
- **宿主自适应**：先探测是否支持选择框/选项工具，再决定弹窗或文本降级
- **上下文分级**：L0 热快照优先，冷规则按需加载，降低 token 与缓存未命中
- **项目无关**：不绑定具体业务、框架、语言、技术栈或某个 AI 产品

## 快速接入

将 `.ai/` 目录复制到目标项目根目录：

```text
your-project/
├── .ai/
├── src/
├── package.json
└── README.md
```

不会覆盖目标项目已有文件。

然后在 AI 编程工具中输入：

```text
请按 .ai/START.md 启动工作流。
目标：{{一句话目标}}
```

## 使用流程

AI 会依次完成以下工作：

1. 识别当前交互语言（静默完成，不占访谈题）
2. 探测宿主选择框/选项能力并选择提问通道（静默）
3. 判断项目模式
4. 询问流程重量
5. 确认任务类型和目标
6. 逐步收集范围、约束和验收标准
7. 给出阶段计划并请求确认
8. 执行开发任务
9. 运行验证并处理问题
10. 更新工作流状态和变更记录

用户不需要手写长篇需求文档。通常只需要选择 AI 提供的选项，或补充简短信息。

## 更好启动

| 场景 | 你说 |
|------|------|
| 新任务 | `请按 .ai/START.md 启动。目标：...` |
| 继续上次 | `请按 .ai/START.md 继续` |
| 更快 | `请按 .ai/START.md 快速启动。目标：... 你推荐我确认` |

AI 会先读短热快照，再走 **resume / 推荐包 / 逐项访谈**，并遵守：先 L0、L1 用 `AGENT.core`/`WORKFLOW.slim`、STATE 只写值、不每轮重读完整冷规则。

## 更顺畅的交互

- 每轮只问一个关键问题，不重复询问已知信息
- 普通阶段完成后按计划自动衔接，只有高风险动作需要再次确认
- 已有项目先做快速梳理，再按任务影响决定是否深入
- 中途可以说“查看进度”“修改答案”“暂停”“继续”“返回上一阶段”
- 会话中断后，AI 从 `.ai/STATE.md` 的 checkpoint 恢复，不需要重新开始

## 项目模式

### Greenfield

适用于空项目或只有基础脚手架的项目：

```text
discover → spec → architecture → plan → build → verify → close
```

### Brownfield / Hybrid

适用于已有代码的项目。AI 会先梳理项目结构、技术栈、入口、脚本、测试和关键模块：

```text
recon → align → impact → plan → build → verify → close
```

- `brownfield`：已有项目，现有文档和代码基本可用
- `hybrid`：已有项目，但工作流文档缺失、空洞或明显过期

## 流程重量

启动时由用户选择，或让 AI 推荐：

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| `full` | 完整阶段全部执行 | 新项目、大功能、架构调整、跨模块改动 |
| `light` | 合并部分分析阶段 | 小功能、局部修复、配置或文档调整 |
| `auto` | AI 根据风险推荐 `full` 或 `light` | 不确定任务规模时 |

如果轻量流程中发现任务风险上升，AI 必须暂停并询问是否升级为完整流程。

任务类型会对照常见大厂研发流（功能迭代、热修、重构、平台、预研、安全、基础设施等）推荐流程重量与阶段侧重，详见 `.ai/WORKFLOW.md` §7。

## 目录说明

```text
.ai/
├── START.md                 # 推荐启动入口（短）
├── README.md                # 工作流包自身的说明
├── AGENT.core.md            # L1 常驻总控（短）
├── AGENT.md                 # 完整总控附录
├── WORKFLOW.slim.md         # L1 流程地图（短）
├── WORKFLOW.md              # 完整流程/大表附录
├── STATE.md                 # 热快照（短 YAML）
├── STATE.schema.md          # STATE 冷说明（按需）
├── ENGINEERING.md           # 通用工程约束
├── ARCHITECTURE.md          # 架构信息模板
├── ROADMAP.md               # 长期规划模板
├── TASKS.md                 # 当前任务和验收标准
├── DECISIONS.md             # 架构决策记录
├── TECH_DEBT.md             # 技术债记录
├── MAINTENANCE.md           # 改工作流时的同步约定
├── CHANGELOG.md             # 工作流变更记录
└── PROMPTS/
    ├── bootstrap.md         # 启动访谈
    ├── recon.md             # 已有项目梳理
    ├── new-feature.md       # 新功能
    ├── refactor.md          # 重构
    ├── bugfix.md            # Bug 修复
    ├── review.md            # Code Review
    └── phase-cards/          # 各阶段门禁卡
```

## 适用工具

这套工作流不依赖特定 AI 编程工具。只要工具能够读取项目文件并与用户对话，就可以使用：

- Codex
- Claude Code
- Cursor
- GitHub Copilot Chat
- 其他支持项目级规则和上下文的 AI 编程工具

工作流会先**静默探测**宿主是否具备可点击选择题 / 选项工具能力：

- 有能力：把问题编译为宿主选项 UI 并弹出
- 能力有模式门控：决策时尽量满足，否则降级
- 无能力：使用 `A/B/C` 文本选项，或对低风险项采用推荐并标注假设

不绑定某个 AI 产品的专有 API；只跟随本轮实际可用能力。

## 设计原则

- AI 负责理解、提案、记录和执行
- 用户负责选择、确认和纠正
- 信息不足时继续访谈，不猜测执行
- 计划外的关键决策必须暂停并重新确认
- 代码、测试和文档都属于交付结果的一部分
